# Лабиринт: актуальная архитектура

## Клиент

`webapp/src/game/LabyrinthApp.tsx` управляет входом, дверями, основным чатом комнаты, заметками и финалом. `PhaserStage.tsx` динамически загружается для фонов и атмосферы. `labyrinth.css` и `base.css` — обязательные стили. `audio.ts` управляет процедурным звуком.

`content.ts` содержит комнаты и тематические вопросы; прежние варианты карточек остаются данными прототипа и не выводятся. `doorOpenings.json` содержит первые реплики; `backend/services/labyrinthTopics.json` — контекст вопросов для сервера. При изменении сценария нужно обновлять оба файла. `QuestInteraction.tsx` не используется.

`state.ts` хранит версионированный путь, историю по комнатам, заметки и настройки. Названия стадий прежнего сохранения оставлены совместимыми; все стадии комнаты кроме `doors` отображают основной чат. Комната завершается явным действием игрока после первого сообщения. AI не открывает двери и не оценивает согласие. После десяти комнат доступна freedom, после одиннадцати — выход.

## API

`POST /api/labyrinth`: `{roomId,message,history,discoveries}`. Ответ: `{response,mode}`, где mode — ai или authored. Клиент ограничивает историю последними 20 сообщениями; сервер принимает максимум 24, сообщение до 2000 символов, до 12 заметок по 200 символов. Невалидный ввод даёт 400, GET — 405, OPTIONS — 204. Ответы no-store.

`backend/services/labyrinthService.js` задаёт фиксированную роль ведущего, тему двери, вопросы и историю. AI должен следовать за ответом игрока и не повторять анкету. `OPENAI_API_KEY` включает AI, `LABYRINTH_MODEL` по умолчанию gpt-4o-mini. Таймаут провайдера 12 секунд без повторов; при ошибке — явно маркированный authored fallback. Он не считается полноценной обработкой смысла ответа.

Express использует `backend/routes/labyrinth.js`; Vercel — `api/labyrinth.js` и общий handler. Клиентский таймаут 15 секунд. При закрытии диалога или переходе в другую комнату запрос отменяется; устаревший ответ не записывается в следующую комнату.

## Конфигурация и поставка

Локальный ключ хранится в игнорируемом `backend/.env`, сервер запускается из backend. На Vercel ключ задаётся в Environment Variables; локальный .env туда не отправляется. Backend не пишет приватную переписку в логи и не сохраняет её в облако.

В Git обязательно включены исходники, CSS, JSON-контекст, WebP-фоны, package-lock и API-entry. node_modules, dist, .env и локальные скриншоты исключены. Проверка сборки из зафиксированных файлов нужна отдельно от успешной локальной сборки, чтобы untracked-зависимости не маскировали неполную поставку.

Перед масштабным запуском остаются лимиты стоимости API, проверки реальных телефонов, оценка качества диалогов и исследования эффективности. Существующие предыдущие маршруты backend не используются новым интерфейсом.
