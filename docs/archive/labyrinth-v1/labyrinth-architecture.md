# Архитектура лабиринта

Телефон — основная платформа. Существующий React + Vite shell содержит lazy-loaded Phaser 3 canvas окружений и HTML overlay квеста. React владеет состоянием маршрута, доступным текстом, дверями и вводом; Phaser рисует фон, частицы и переходы. Canvas не определяет доступность прохождения. Desktop использует те же правила и портретную безопасную композицию.

## Мобильный контракт

Overlay использует dynamic viewport и safe-area, touch targets минимум 44 px, скроллируемую панель чата с доступным вводом при открытой клавиатуре. Canvas получает resize и ограниченную resolution; следующая сцена загружается по потребности. Пропавшая картинка заменяется градиентом. Background visibility приостанавливает анимацию и звук, прогресс сохраняется после действий. Reduced motion убирает частицы и параллакс. Контроль звука, истории и всех дверей доступен HTML.

Web Audio реализован отдельным менеджером: unlock только после жеста пользователя (особенно Safari), плавная смена профиля, mute/volume, pause при background, явный новый жест при невозможности resume. Смысл сцены не зависит от звука. Подробные сцены и партитура описаны в labyrinth-production.md и labyrinth-audio.md.

## Маршрут и данные

Фиксированный room graph содержит pleasure, stress, origin, company, ritual, loop, price, tomorrow, withdrawal, world, freedom. Все обязательные темы посещаются благодаря фронтовым условиям маршрута; AI не открывает двери и не присуждает согласие. Авторские задания работают без сервера. История хранится отдельно для каждой комнаты. Ответ AI — дополнительный разговор, не единственный способ продвинуться.

Версионированное локальное сохранение содержит текущую комнату, завершённые задания, ответы, записи, per-room диалоги и настройки. В этой итерации нет Supabase cloud persistence для лабиринта. Ошибка localStorage должна отображаться честно; нельзя обещать синхронизацию между устройствами. Не отправлять всю локальную историю в API без необходимости.

## API

POST /api/labyrinth

```json
{
  "roomId": "stress",
  "message": "После работы хочется выдохнуть",
  "history": [{"role": "user", "content": "Я курю после работы"}],
  "discoveries": ["Перекур даёт паузу"]
}
```

200: `{ "response": "…", "mode": "ai" }` или `{ "response": "…", "mode": "authored" }`. UI явно обозначает авторский режим: fallback не притворяется индивидуальной AI-обработкой. Максимум 24 сообщения history; message/content максимум 2000 символов; discoveries максимум 12 строк по 200 символов. history и discoveries опциональны. Недопустимый roomId, роли или размер дают 400. GET возвращает 405. OPTIONS 204. Cache-Control: no-store.

Серверный системный prompt фиксирован; пользователь не может передать произвольный system prompt. В истории разрешены только user/assistant. Runtime OPENAI_API_KEY включает AI, LABYRINTH_MODEL выбирает модель (default gpt-4o-mini). Provider timeout 12 секунд, без retries; сбой, пустой ответ или отсутствие ключа возвращают тематический authored fallback. Ответ ограничен 1200 символами. API не пишет разговор в логи и не сохраняет его в облако.

Один handler используется Express route и Vercel root entry. Vercel maxDuration 20 секунд. Endpoint для публичной демо-игры не имеет аккаунтного лимита стоимости: перед крупным публичным запуском нужен выбранный механизм rate limit/budget. Это ограничение запуска, не блокировка авторского прохождения.

## Проверка

Backend meaningful tests проверяют все комнаты без ключа, bounded payload, запрещённые роли, fixed system policy, runtime model, provider failure, disagreement, статусы HTTP и no-store. Frontend проверки: portrait 390×844/360×740, safe-area, keyboard, reload resume, полный authored маршрут, server unavailable, reduced motion, звук после жеста и скрытие вкладки. Production build отдельно от runtime server/API.
