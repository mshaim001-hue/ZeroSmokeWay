# Лабиринт: актуальная архитектура

> Этот документ описывает классический Лабиринт (`?version=classic`). На главной странице сейчас трёхкомнатный прототип; актуальное устройство — [prototype-implementation.md](design/prototype-implementation.md).

## Клиент

`webapp/src/game/LabyrinthApp.tsx` управляет входом, дверями, основным чатом комнаты, заметками и финалом. `PhaserStage.tsx` динамически загружается для фонов и атмосферы. `labyrinth.css` и `base.css` — обязательные стили. `audio.ts` управляет процедурным звуком.

`content.ts` содержит диалоговые комнаты: id/title/subtitle/profile/opening/topicIds/questions/connections. steps, choices и objects удалены из активной схемы. Первые реплики используются непосредственно из content.ts; `doorOpenings.json` сохраняется как синхронизированная копия; `backend/services/labyrinthTopics.json` — контекст вопросов для сервера. При изменении сценария нужно обновлять оба файла. `QuestInteraction.tsx` перенесён в архив.

`state.ts` хранит версионированный путь, историю по комнатам, заметки и настройки. Схема v2 использует conversation/doors и progress с phase/evidence/ready. v1 мигрирует без удаления переписки и завершённого финала. Комната завершается только после AI-ready, четырёх цитат из сообщений игрока и трёх разных содержательных реплик. Клиент повторно проверяет происхождение цитат; старые completed доступны как архив, а не повторное завершение. AI оценивает полноту разбора, а переход выполняет игрок; согласие не является условием. Граф двусторонний, первые двери ранжируются расстоянием через пройденные комнаты, остальные доступны через общий выбор. personal — отдельная необязательная дверь. После десяти комнат доступна freedom, после одиннадцати — выход.

## API

`POST /api/labyrinth`: `{roomId,message,history,discoveries}`. Ответ: `{response,mode,progress,issue?}`, где progress содержит phase, четыре цитаты evidence и ready; mode — ai или authored. Клиент передаёт до 20 сообщений: начало разговора и последние реплики; вся переписка остаётся в локальном журнале; сервер принимает максимум 24, сообщение до 2000 символов, до 12 заметок по 200 символов. Невалидный ввод даёт 400, GET — 405, OPTIONS — 204. Ответы no-store.

`backend/services/labyrinthService.js` задаёт фиксированную роль ведущего, тему двери, вопросы и историю. AI должен следовать за ответом игрока и не повторять анкету. `OPENAI_API_KEY` включает AI, `LABYRINTH_MODEL` по умолчанию gpt-4o-mini. Таймаут провайдера 12 секунд без автоматических повторов. Модель возвращает JSON. Для gpt-6-luna используются max_completion_tokens и reasoning_effort none; выбранная пользователем модель сохраняется. При ошибке — честный authored fallback с ready:false и безопасным issue (ключ, доступ, лимит, модель, таймаут, несовместимый запрос или ответ). Он не повторяет opening и не подменяет обработку сообщения.

Express использует `backend/routes/labyrinth.js`; Vercel — `api/labyrinth.js` и общий handler. Клиентский таймаут 20 секунд. Повтор отправляет прежнее сообщение без добавления второй пользовательской реплики. При закрытии дополнительного диалога или переходе в другую комнату запрос отменяется; устаревший ответ не записывается в следующую комнату.

## Конфигурация и поставка

Локальный ключ хранится в игнорируемом `backend/.env`, сервер запускается из backend. На Vercel ключ задаётся в Environment Variables; локальный .env туда не отправляется. Backend не пишет приватную переписку в логи и не сохраняет её в облако.

В Git обязательно включены исходники, CSS, JSON-контекст, WebP-фоны, package-lock и API-entry. node_modules, dist, .env и локальные скриншоты исключены. Проверка сборки из зафиксированных файлов нужна отдельно от успешной локальной сборки, чтобы untracked-зависимости не маскировали неполную поставку.

Совместимость выбранной модели проверена по [официальной документации OpenAI](https://developers.openai.com/api/docs/models/gpt-6-luna) и живым синтетическим запросом.

Перед масштабным запуском остаются лимиты стоимости API, проверки реальных телефонов, оценка качества диалогов и исследования эффективности. Существующие предыдущие маршруты backend не используются новым интерфейсом.
